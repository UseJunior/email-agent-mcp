## Changes

- Gmail setup chooses the mailbox name after Google sign-in, once the account is known. Without `--mailbox`, an account that is already configured keeps its name; a new account gets a name derived from its address (`jane@example.com` → `jane-example`) that no mailbox on any provider uses, confirmed in a terminal (#289, #290).
- An explicit `--mailbox <alias>` no longer requires a TTY; setup prints which account it linked. New `--confirm-account <email>` (also sent to Google as the login hint; a different account fails and saves nothing) and `--yes` / `-y` (#290).
- If `--mailbox` names a mailbox linked to a different account, setup never overwrites it: without a terminal it saves the sign-in under a derived name and exits 1, so no second sign-in is needed (#290).
- New `email-agent-mcp mailbox rename <old> <new> [--provider]`, which refuses names, addresses and token filenames used by any other mailbox (#290).
- Fix: Gmail and Microsoft mailboxes for the same address no longer overwrite or delete each other's token files. Gmail records move to `<key>.gmail.json` when needed (#290).

Validated with three Codex review rounds, CI, a post-merge draft-only smoke (rename, collision refusals, renamed-alias reads), and live broker sign-ins covering naming after sign-in, keeping an existing name, non-TTY `--mailbox`, and cancelled sign-ins saving nothing. No mail sent.
